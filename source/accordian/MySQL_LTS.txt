Q1: MySQL Innovation 트랙과 LTS 트랙의 차이점은 무엇인가요?
A1: Innovation은 최신 기능을 빠르게 도입하지만 지원 주기가 짧은 트랙이며, LTS는 기능 변경을 최소화하고 보안 패치와 버그 수정 위주로 최대 8년간 지원하는 안정적인 트랙입니다.

Q2: MySQL 8.0의 공식적인 지원 종료 시점은 언제인가요?
A2: MySQL 8.0 커뮤니티 버전은 2026년 4월에 지원이 종료(EOL)되며, Amazon RDS MySQL 8.0의 표준 지원은 2026년 7월 31일에 종료될 예정입니다.

Q3: 클라우드 환경에서 '강제 업그레이드'가 발생하는 이유는 무엇인가요?
A3: Oracle HeatWave와 같은 서비스는 특정 버전이 지원 불가 상태가 되면 시스템 가용성 유지를 위해 사용자의 동의 없이도 차기 버전으로 자동 업데이트를 수행하는 정책을 가지고 있습니다.

Q4: AWS RDS에서 제공하는 Extended Support란 무엇인가요?
A4: 표준 지원이 종료된 후에도 특정 버전의 보안 패치를 계속 받기 위해 지불하는 유료 서비스입니다. 이는 임시방편일 뿐 시간이 지날수록 비용 부담이 급격히 증가하는 구조입니다.

Q5: MySQL 8.4 LTS로 마이그레이션하면 어떤 이점이 있나요?
A5: 최대 8년이라는 긴 지원 기간을 확보할 수 있습니다. 잦은 업그레이드 없이 안정적인 운영 환경을 유지할 수 있으며, 클라우드 추가 과금 리스크를 해소하여 운영 비용을 최적화할 수 있습니다.

Q6: 강제 업그레이드 시 발생할 수 있는 '파괴적 변경' 리스크는 무엇인가요?
A6: 사전 검증 없이 상위 버전으로 업데이트될 경우, 하위 호환성이 없는 변경 사항으로 인해 기존 쿼리가 동작하지 않거나 시스템 성능이 저하되는 등의 심각한 장애가 발생할 수 있습니다.

Q7: AWS RDS MySQL 8.0을 계속 사용할 때 발생하는 비용 부담은 어느 정도인가요?
A7: 표준 지원 종료 후 Extended Support를 사용하면 vCPU당 추가 비용이 발생합니다. 특히 3년 차에는 비용이 1~2년 차 대비 100% 인상되는 등 재무적으로 큰 부담이 됩니다.

Q8: 안정적인 마이그레이션을 위해 지금 당장 준비해야 할 것은 무엇인가요?
A8: 사용 중인 모든 DB 인스턴스의 버전과 의존성을 조사해야 합니다. 2026년 초까지 8.4 LTS 환경을 구축하여 쿼리 호환성과 성능 검증을 마치는 전략적 로드맵 수립이 필요합니다.

Q9: AWS RDS MySQL 8.0 쓰고 있는데 추가 비용 안 나오게 하려면 언제까지 버전을 바꿔야 하나요?
A9: 아마존 RDS의 표준 지원이 2026년 7월 31일에 끝나거든요. 그러니까 추가 요금을 피하시려면 늦어도 2026년 상반기까지는 8.4 LTS 버전으로 마이그레이션을 완료하시는 것이 안전합니다.

Q10: 이번에 새로 나온 MySQL 8.4 LTS로 업데이트하면 이전보다 시스템이 정말 더 안정적일까요?
A10: 네, LTS 버전은 새로운 기능을 추가하기보다 보안과 버그 수정에 집중해서 8년 동안 지원하기 때문에, 자주 버전을 바꾸지 않아도 돼서 운영하시기에 훨씬 예측 가능하고 안정적일 거예요.
